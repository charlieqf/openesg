### 两个需要特别解释的现状

**新建演示项目并不是空白项目。** `projects-data.js:35` 选择 `missing` 场景，而 `demo-data.js` 的场景基线含已批准的历史 BUILD-001。当前页面已明确提示它是演示样例，因此不认定为隐藏的数据错误；但它确实不能替代“一个新客户从零建报告”的设计，C05 要补的是这段旅程。

**提示词不是没有，而是发布后的旅程尚未演完整。** `design-review.js:165` 只保存本页 Map，`:170` 展示版本与 Diff，`:92` 为 P08 组合预置配置，`:99` 明确 P07 编辑不传给 P08。本轮不推翻此前刻意保留的静态边界，建议补“发布前/发布后/被退回/沿用旧版”样例，而不是偷偷转入真实持久化、审批或模型开发。

## 6. 明确不是本轮要开发的功能

- 真实数据库与多租户权限；本地文件系统桥接、文件监听；PDF/Office/OCR 解析；后台 DAG 调度、幂等/缓存/并行执行；真实模型调用；提示词发布引擎；正式 DOCX/PDF/XLSX 渲染。
- 这些能力中，界面必须让用户理解的状态需要画出来；计算、服务和权限执行本身仍可保持模拟。
- 当前 DOCX/PDF 禁用、虚构监管正文、模型输出占位和页面内提示词草案已作明确标识，不应作为“漏了按钮”的问题反复修复。应改进的是用户旅程与状态说明。

本轮只新增此核对文档，没有修改任何 HTML/JS/CSS、生产源码、既有计划或历史验收结论，也没有进行 Cloudflare 发布或 Git 提交推送。
